# API design

1. Inspecciona convenciones existentes y consumidores.
2. Define recursos/operaciones, tipos, validación, autenticación/autorización y semántica de errores.
3. Especifica paginación, filtros, orden, idempotencia y límites si aplican.
4. Define compatibilidad y estrategia de evolución/versionado.
5. Considera timeouts, reintentos, rate limits y observabilidad.
6. Añade ejemplos de request/response y pruebas de contrato.
7. Evita exponer detalles internos o datos sensibles.

## Output
Contrato propuesto, errores, seguridad, compatibilidad, ejemplos y plan de pruebas.
