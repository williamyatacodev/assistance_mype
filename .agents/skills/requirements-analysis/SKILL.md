# Requirements analysis

1. Reformula el objetivo como resultado observable, sin repetir innecesariamente la petición.
2. Identifica usuarios/actores, comportamiento esperado, restricciones, dependencias y fuera de alcance.
3. Separa hechos confirmados, supuestos y preguntas bloqueantes.
4. Define criterios de aceptación comprobables, incluidos errores y límites.
5. Clasifica riesgo: datos, seguridad, compatibilidad, costo, producción.
6. Si falta información no bloqueante, declara un supuesto conservador y sigue. Si es bloqueante, pregunta antes de cambios irreversibles.

## Output
- Objetivo
- Alcance / fuera de alcance
- Criterios de aceptación numerados
- Supuestos y preguntas
- Riesgos
